Backup and restore

Two kinds of copy: Settings only, a small file, and Full without media, which rebuilds the server on a new install.

When backups are made

Starboard can make the backups by itself at 03:00, when the server is quiet, and keep only the newest few.

When backups are made

Full without media

Starboard, its plug-ins and every app's settings and database, encrypted with a password you choose. Restore it on this server to go back to an earlier day, or on a new install to get the same server back. Nothing that can be downloaded again goes in.

Where the copies goOn another disk than the system disk, so a copy outlives it. Starboard keeps the newest 5 here.Srv, Media, Backups, Starboard/srv/media/backups/starboard

Restore puts one back on this server. For a new server, install Starboard there and choose Restore a backup in the set-up. Each app stops for a moment while its own folder is copied.

Where backups go

After each full backup, Starboard copies it to every place that is on and keeps the newest few in each. A failed disk, a theft or a fire then does not take every copy. A backup counts as safe only when each place has read it back. Nothing runs between copies.

Add a place

Choose where else a backup can go. You can add the same kind of place more than once, such as two cloud accounts.

Server settings backup, encrypted

The server's own backup job writes a zip of the apps' settings with API keys and passwords. Starboard sends it to the same places, but only after encrypting it with rclone crypt, and only after its key is made. The plain file is never uploaded.

Starboard's settings, your apps and their API keys, categories, plug-in settings and logo choices, in one small file. Not your password, and not the apps' own settings.
